# Root requirements -- the ONE file Azure App Service (Oryx) installs.
#
# Oryx only reads a requirements.txt at the repository root, but this app runs
# three processes with three requirement sets (backend/, NewBusiness/backend/,
# gateway/). This is their union. The per-project files stay for local dev,
# where you may want to run a single engine on its own; they are pinned to the
# identical versions, so there is one dependency set either way and no
# possibility of the deployed app resolving something different.
#
# EXACT pins, not floors, for one specific reason: both *_latest.joblib files
# are pickles of fitted scikit-learn pipelines, and scikit-learn gives no
# cross-version pickle-compatibility guarantee. With "scikit-learn>=1.3" a
# deploy would install a much newer sklearn and load a model fitted on 1.3.2 --
# an InconsistentVersionWarning nobody reads at best, silently different
# predictions at worst. Changing anything in the ML block below means
# retraining and re-publishing, not just editing this file.
#
# If you edit this, edit backend/requirements.txt and
# NewBusiness/backend/requirements.txt to match.
